# 看板执行记录折叠展示设计

日期：2026-09-01
状态：设计已确认（含在线原型演示），待实施

## 背景

看板「执行记录」按行平铺展示某天全部运行记录。runs 表行键 =（窗口, 任务, 日期, slot），
每次手动触发都会给终态后的窗口开启新轮次（slot+1），8/12 小时间隔任务本就一天多轮，
导致同一窗口同一任务出现多行，表格行数膨胀、与顶部统计口径混杂。

## 目标

同一窗口同一任务的多轮记录**默认折叠为一行**（显示最新一轮），历史轮次可展开查看；
只改前端展示层，后端/调度/slot 模型/重试逻辑零改动，审计轨迹完整保留。

## 设计

### 折叠规则

- 前端按 `(profileId, taskKey)` 分组，组内按 `slot` 倒序；
  顶层行 = 最新 slot 一轮，其余轮次为该行的子行（antd Table 树形数据）
- 8/12 小时间隔任务与日常任务同规则混排，无特殊处理
- 组内只有 1 轮时不渲染展开图标
- 顶层行展开图标旁显示「历史 N 轮」计数（N = 组内轮数 - 1）

### 展开区（嵌套小表）

列：`轮次(#slot) | 开始时间 | 结束时间 | 总耗时 | 状态 | 错误 | 截图 | 操作`
- 不重复顶层已有的窗口/任务列
- 每行保留各自截图「查看」与「重跑/执行」操作

### 统计口径统一

顶部统计卡按**每窗口每任务最新一轮**计数（success/failed/running/skipped 等），
与折叠后表格行数一致；不再按全部行数累计。

### 筛选作用域

状态/任务/窗口搜索只作用于**最新轮**（顶层行）；展开出的历史行不被二次过滤，
保持每组的完整历史。

### 排序

维持现有 API 返回顺序（profile.id, taskKey, slot），分组后组顺序按首次出现顺序。

## 范围外

- 后端接口、DB、调度、触发语义、重试逻辑均不改动
- profiles 页矩阵与详情不改动
- 不做「永久只显最新轮」的丢弃式过滤（折叠保留审计可见性）

## 测试

  多轮分组、最新轮置顶、单轮无子行、统计计数按最新轮）
